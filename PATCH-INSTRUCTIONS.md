# Патч контроля отчётов по «сарафану» для sinai-news-report

## Состав

- `referral_control.py` — фоновая сверка amoCRM и Telegram-группы.
- `config.json` — четыре менеджера, их amoCRM ID и Telegram ID, ID поля `Менеджер` и настройка этапа.
- `apply_referral_patch.py` — безопасная интеграция модуля с текущим `main.py`; проверяет все якоря и компилирует результат до записи.
- `tests/test_referral_control.py` — тесты парсинга, сопоставления менеджеров, дневной сверки, месячной даты и пагинации.

## Установка

1. Сделайте резервную копию текущей папки проекта.
2. Распакуйте содержимое архива **в корень существующего** `sinai-news-report`, рядом с `main.py`.
3. Из корня проекта выполните:

   ```bash
   python apply_referral_patch.py
   ```

   Скрипт сохранит `main.py.before-referral-control.bak`, добавит интеграцию в `main.py`, обновит `.env.example` и допишет раздел в `README.md`. Если исходный `main.py` не совпадает с ожидаемой версией, скрипт остановится до изменения файлов.
4. Добавьте в существующий `.env`:

   ```dotenv
   REPORTS_GROUP_CHAT_ID=
   REFERRAL_POLL_SECONDS=60
   MONTHLY_REPORT_TIME=23:59
   MANAGER_FIELD_ID=518097
   ```

   Остальные переменные `.env`, включая `REPORT_TG_BOT_TOKEN`, `REPORT_CHAT_ID`, `MANAGER_IDS`, `AMOCRM_BASE_URL` и OAuth-настройку, оставьте из текущей установки.
5. В BotFather отключите privacy для отчётного бота командой `/setprivacy` → Disable либо сделайте его администратором группы. Удалите и добавьте бота в группу заново после изменения privacy.
6. Пока `REPORTS_GROUP_CHAT_ID` пустой, запустите бота и отправьте тестовое сообщение в группу. В логе будет строка `Получено сообщение из группы <ID>`. Впишите этот отрицательный ID (обычно начинается с `-100`) в `.env` и перезапустите отчётный бот.
7. Проверьте тесты:

   ```bash
   venv/bin/python -m unittest discover -s tests -v
   ```

8. Перезапустите только сервис `sinai-news-report`.

## Как работает

- Раз в минуту фоновый поток запрашивает только события `lead_status_changed`, отфильтрованные по целевому этапу в amoCRM. Обработчик Telegram не ждёт amoCRM и не делает сетевых CRM-запросов.
- Фактические `pipeline_id` и `status_id` автоматически находятся по точным названиям `Отдел продаж` и `сарафан`; найденные числовые значения записываются в лог. В `config.json` их можно затем зафиксировать вместо `0`.
- Первичная установка начинает сбор с момента запуска с пяти минутами технического перекрытия для API; прежние сделки до этого окна автоматически не штрафуются.
- Для привязки менеджера сначала проверяется поле `Менеджер` с ID `518097`, затем `responsible_user_id`. В месячном отчёте отдельно показываются сделки, где менеджер не определился; за них штраф автоматически не назначается.
- Отчёт должен быть отправлен в ту же группу тем же менеджером и в ту же календарную дату, что и переход сделки в этап. Одинаковый ID учитывается один раз за дату. Отчёт другого менеджера или сообщение на следующий день не снимает штраф.
- В дневной отчёт за предыдущий день добавляются сделки без отчёта. При полном комплекте появляется подтверждение, что отчёты по всем сделкам предоставлены.
- В последний календарный день месяца в `MONTHLY_REPORT_TIME` (по умолчанию 23:59) отправляется итог `количество × 500 ₽`. Кнопки менеджеров открывают список сделок с пагинацией по пять ссылок.
- Все данные контроля лежат в `REPORT_STATE_PATH`, отдельно от исходной SQLite. amoCRM используется только на чтение.

## Важные ограничения и безопасность

- Числовые ID воронки и этапа не опубликованы в документации amoCRM и зависят от аккаунта. Поэтому в конфиге стоят `0`: приложение само запросит `GET /api/v4/leads/pipelines`, найдёт точное совпадение названий и выведет числовые ID. Если названия не уникальны, приложение остановится с понятной ошибкой и попросит заполнить ID вручную.
- Для работы нужны права чтения воронок, событий и карточек сделок. OAuth-токен берётся тем же способом, что и в существующем проекте: из `AMOCRM_ACCESS_TOKEN` либо `settings.oauth` базы основного бота.
- Токен Telegram, опубликованный в переписке, необходимо немедленно перевыпустить через BotFather и заменить в `.env`. Не добавляйте `.env` в Git.
- Репозиторий GitHub не изменён автоматически: создание ветки через подключённый GitHub-инструмент было отклонено правами доступа (HTTP 403). Архив содержит патч для локального применения.
